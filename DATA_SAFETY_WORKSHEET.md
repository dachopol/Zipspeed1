# Zipspeed — Data Safety Working Sheet

This is an engineering worksheet, not a final Play Console answer. Re-check it against the signed production AAB and every enabled SDK before submission.

## Data flows visible in the current source

### Network measurement

When the user runs a network test, the app sends HTTP requests and test payloads to configured network endpoints. Those servers necessarily receive normal network request metadata such as the user's IP address.

Purpose: app functionality / network measurement.

### Public IP lookup

The app can query Cloudflare metadata and can fall back to `api.ipify.org` to obtain the user's public IP.

Purpose: app functionality / network diagnostics.

### Optional location

Fine/coarse Android location permissions exist for optional GPS mode. The normal speed test no longer requests or requires GPS.

Purpose when user enables it: app functionality / optional location display.

Before release, confirm whether precise location is truly necessary. If approximate location is sufficient, reduce the permission/data scope.

### Local history

Completed speed-test results can be stored locally using Room. Fields include measured Download, Upload, latency, jitter, optional packet-loss field, server/route label, network-type label and timestamp.

Purpose: app functionality / user history.

### Sharing/export

The user can explicitly share a result or export history as CSV/JSON through Android sharing.

Purpose: user-requested app functionality.

### External status links

Tapping an outage/status link opens an external website. That external destination receives the normal request generated by the browser/app selected by Android.

### Ads / billing

Current source does not have active Google Mobile Ads or Google Play Billing runtime integration. If either is added, this worksheet and the Play Console Data Safety form must be updated from the actual SDK behavior before release.

## Items to verify in the final artifact

- Whether any analytics/crash-reporting SDK is present.
- Whether any ad SDK is present.
- Whether Play Billing is present.
- Whether exact or approximate location is collected/transmitted.
- Whether public IP is only displayed transiently or stored anywhere.
- Whether shared/exported history can include public IP.
- Whether app backup includes local history/preferences.
- Whether any SDK collects device identifiers, diagnostics or usage data.
- Whether all transmitted data uses encrypted transport.
- Retention/deletion behavior for local history.
- Contact details and Privacy Policy URL.

## Accuracy rule

Never answer “no data collected” solely because Zipspeed has no backend. Third-party SDKs and remote network endpoints can still receive data. Play Data Safety answers must be based on the final production behavior, including third-party libraries.
